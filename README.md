# 生活助手

一个给班级生活委员用的**宿舍人员情况填报与汇报系统**：同学打开网页选自己的寝室，点几下谁在寝、谁不在就交上来了；系统自动统计、每天导出一份 Excel 存档，并按时把汇总发到 QQ 群、把未填报提醒推给生活委员。

- **两个端口分开**：`:8090` 给同学和寝室长（公开），`:8091` 给管理员（管理接口只在这个端口开放）
- **寝室长密码可选**：不设密码时谁都能直接选寝室填报；设了密码，寝室长验证后进入只属于自己的界面
- **账号密码登录**：管理员用用户名 + 密码登录管理端，能添加多个管理员账号、随时改密码；
- **班费管理**：导入班费收支明细表，在线增删改，一键把最新费用 / 选定费用 / 全部费用发到班级群
- **填写日志可追溯**：谁在什么时间、用什么设备（手机/电脑型号、浏览器/微信）、从哪个 IP 提交的，管理员一页看全
- 后端：FastAPI + SQLAlchemy + SQLite（单文件数据库）+ APScheduler
- 前端：原生 HTML/CSS/JS + 本地内置 Chart.js，**无构建步骤、无外部 CDN**，断网也能用

## 一、功能清单

### 1. 入口页：选寝室 → 直接填写

- 打开网站就是**「请选择你的寝室」**，寝室以卡片列出（宿舍号、寝室长、人数、完整名称），支持搜索。
- 点一下自己的寝室，**直接进入填写界面**：逐人点「在寝 / 不在」→ 不在的选原因（回家 / 病假 / 事假 / 外出 / 实习 / 参加比赛，可改）→ 填备注 → 提交。
- 入口页还能看到今晚进度（已填几间、在寝几人）和还没填报的寝室清单。
- 页面上有「我是寝室长（验证）」和「管理员进入」两个入口。

### 2. 人员信息按寝室分组管理（需管理员设备）

- Excel（`.xlsx`）/ CSV 导入名单：自动识别列名、按宿舍号分组、**合并单元格自动向下填充**、宿舍号规范化（`新区校区6号学生公寓207` → `6-207`，原始名称保留显示）。
- 单个寝室、单个成员的增 / 删 / 改；寝室可停用（保留历史填报）或彻底删除。
- 导入模板下载、全部名单导出。

### 3. 每日填报与 Excel 存档

- 一个寝室一天一条记录，重复提交覆盖；可补填最近 7 天。
- 导出文件名 `宿舍填报_2026-10-10.xlsx`，每天一张「汇总」表 + 一张「明细」表，缺人标红、齐全标绿、未填报标灰。
- 可导出单日 / 区间（最多 62 天）/ 按天打包 zip；**每天 23:30 自动导出**到服务器 `exports/`，自动只保留最近 400 个。

### 4. 消息推送

- **每晚 22:40 向 QQ 群汇报**当天情况（QQ 官方机器人 / QQ 开放平台），默认内容形如：

  ```text
  【2026-10-10 宿舍晚归情况汇报】
  示例大学 物联网25-2
  应查 14 间，已报 7 间，未报 7 间
  在寝 23 人 / 应到 24 人，缺勤 1 人次
  ——————
  ✅ 6-213：齐全 4 人
  ⚠ 6-214 缺 1 人：赵嘉毅（外出，已向辅导员报备）
  ❓ 6-215：未填报
  ——————
  未填报宿舍：4-153、4-212、4-214、6-207、6-209、6-212、6-215
  汇报人：生活委员  22:40
  ```

- **定时提醒**：在「提醒推送」页可添加多条（每条自定义时间、内容，可选 @全体成员），内容支持 `{missing}`、`{missing_list}` 等变量。
- 时间、群号、Token、消息模板全部在网页上改，保存后定时任务立即重载。
- 寝室长也能直接在群里回 `6-213 人齐` 或 `6-213 缺 张三、李四`，系统自动记录。
- 所有发送都有推送日志（成功 / 失败 / 原文 / 失败原因）。

### 5. 可视化与其它

- **数据看板**：今日填报率、在寝/应到、近 14 天趋势、今日状态环图、各寝室今晚情况、最新填报动态、本月最不积极寝室、缺勤汇总。
- **统计图表**：按**天 / 周 / 月**切换、在寝与缺席人数、填报时间分布、各寝室填报率排行榜、任意日期逐寝室明细。
- 操作日志（谁做了什么、来源 IP）、数据库一键备份、清空业务数据（保留配置，需输入“清空”确认）。

## 二、两个端口与三种身份

### 端口分工

| 端口 | 默认 | 谁能用 | 提供什么 |
| --- | --- | --- | --- |
| **公开端口** | `8090` | 任何人 | 「选择寝室」入口页、每日填报、数据看板、统计图表、填报记录；寝室长的专属界面也在这里 |
| **管理端口** | `8091` | 需要管理员**账号登录** | 班费管理、账号管理、填写日志、管理控制台、宿舍与人员、提醒推送、系统配置 |

两个端口是**同一个服务**（一条 `python run.py` 同时监听），但**接口层面做了隔离**：

- 公开端口上，所有管理接口一律返回 404（改配置、增删寝室、导入名单、账号管理、班费、清空数据……全都进不来）
- 前端也按端口区分界面：公开端口看不到任何管理菜单，管理端口只显示管理菜单
- 端口可用环境变量改：`DORM_PORT`（公开）、`DORM_ADMIN_PORT`（管理）

### 三种身份

| 身份 | 怎么进入 | 能做什么 |
| --- | --- | --- |
| **普通填报（访客）** | 打开公开端口 → 选寝室 | 填任意寝室、看数据看板与统计、看填报记录、导出 Excel；对**没设密码**的寝室，还能直接修改这间寝室的成员信息 |
| **寝室长** | 公开端口 →「我是寝室长（登录）」→ 宿舍号 + 密码 | 只看到自己寝室，填报和查看都锁定在本寝室 |
| **管理员** | 管理端口 → 用**管理员工号 + 密码**登录 | 全部页面：总览、班费管理、账号管理、数据看板、统计图表、填报记录、填写日志、控制台、人员管理、推送配置、系统配置 |

### 寝室长密码是「可选」的

- **不设置密码**（默认）：同学打开公开端口选寝室就能填，寝室长也是同样操作，**所有人都能正常访问**。
- **设置了密码**：这就是这间寝室的"锁"。**该寝室的所有写操作（填报、补填、修改成员）都必须先用该寝室的寝室长账户验证**：
  - 没验证的人：连提交都会被拒绝，网页上会提示"这间寝室已由寝室长设置密码"，并给一个「立即验证」按钮；
  - **别的寝室的寝室长也进不来**（跨寝室会被拒绝）；
  - 管理员在**管理端口**（8091）不受限制，随时能查看和代填。
- 寝室长验证后进入专属界面：左侧只剩「每日填报」，寝室选择框锁定自己的寝室，看不到也改不了别人寝室的数据。
- 密码由管理员在「管理控制台 → 寝室长验证密码」里**给选定的寝室逐个管理**：
  | 操作 | 说明 |
  | --- | --- |
  | **设密码 / 改密码** | 在输入框里填自己想设的密码（≥4 位）→ 点按钮 |
  | **重置** | 随机生成一个新密码，**旧密码立即失效**（寝室长忘密码时用这个） |
  | **取消密码** | 清掉密码，这间寝室恢复"谁都能直接选它填报" |
  | 给没有密码的寝室批量生成 | 一次性给所有未设密码的寝室各生成一个，并给出可复制的清单 |
- 忘记密码、想换密码、想取消限制，都能在控制台一键完成。
- 没设密码的寝室想进寝室长界面时会提示"这间寝室还没有设置验证密码，直接选寝室填写即可"。

### 管理员账号

第一次安装时系统会自动创建一个超级管理员：

| 项目 | 值 |
| --- | --- |
| 登录地址 | `http://你的服务器:8091`（管理端口） |
| 账号 | `admin` |
| 初始密码 | 安装时打印的 6 位数字（也存在数据库 `settings.admin_code` 里） |

```bash
# 服务器上查看账号清单和初始密码
cd /www/dorm && .venv/bin/python scripts/admin_account.py --list

# 忘了密码：重置（不影响任何数据）
.venv/bin/python scripts/admin_account.py --reset
.venv/bin/python scripts/admin_account.py --reset --password 我的新密码

# 新建一个管理员账号
.venv/bin/python scripts/admin_account.py --new teacher01
```

登录后：

- **「账号管理 → 修改密码」** 改自己的密码（每次登录后建议先改掉初始密码）；
- **「账号管理 → 添加账号」** 可以再建多个管理员账号（比如班主任一个、生活委员一个）；
- **「账号管理 → 寝室长账号」** 给寝室建寝室长账号（用户名就是宿舍号），或在「管理控制台 → 寝室长验证密码」里设密码 / 重置 / 取消密码。

### 管理访问码（历史遗留）

```bash
# 服务器 / 本机查看（没有就自动生成）
cd /www/dorm && .venv/bin/python scripts/show_admin_code.py

# 顺便看看已经授权了哪些设备
.venv/bin/python scripts/show_admin_code.py --devices
```

- 在**管理端口**（`http://IP:8091`）输入访问码即可把当前设备加入授权名单；第一台设备用命令行拿到的访问码激活。
- 「管理控制台」里可以**修改访问码**（自己定，4 位以上，字母数字 `- _ @` 都行）、随机重新生成、查看已授权设备、停用或移除设备。
- 想彻底关掉设备门禁：在「系统配置 · 基本设置」把 `admin_access` 设为 0。

## 三、技术栈与目录结构

| 层 | 选型 |
| --- | --- |
| Web 框架 | FastAPI（含 uvicorn） |
| 数据库 | SQLite（单文件 `data/app.db`），SQLAlchemy 2.x ORM |
| 定时任务 | APScheduler 3.x（随服务启动） |
| 外部请求 | httpx（调用 QQ 官方机器人接口） |
| Excel | openpyxl |
| 二维码 | segno（离线生成 PNG） |
| 密码与令牌 | 标准库 PBKDF2 + itsdangerous 签名令牌 |
| 前端 | 原生 HTML/CSS/JS + 本地 Chart.js |
| 部署 | systemd（默认 8090 端口），可选 Nginx 反代 |

**环境变量**

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DORM_HOST` | `0.0.0.0` | 监听地址 |
| `DORM_PORT` | `8090` | 公开端口：同学填报 + 寝室长界面 |

| `DORM_RELOAD` | 空 | 设 `1` 开热重载（开发用） |

## 四、本地运行（Windows）

```powershell
cd E:\Document\code\生活助手
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# 慢的话： -i https://mirrors.aliyun.com/pypi/simple/

.\.venv\Scripts\python.exe run.py
```

- 同学 / 寝室长：<http://127.0.0.1:8090>
- 管理员：<http://127.0.0.1:8091>
- 手机访问（同一 WiFi）：`http://电脑局域网IP:8090`，需要放行防火墙：

  ```powershell
  New-NetFirewallRule -DisplayName "生活助手 8090" -Direction Inbound -Protocol TCP -LocalPort 8090 -Action Allow
  ```

- 也可以双击 `deploy\start.bat`（首次运行自动建虚拟环境、装依赖）。
- 第一次打开**管理端口**（8091），先执行 `scripts/show_admin_code.py` 拿到管理访问码，输入后这台设备就被授权了；之后可以在控制台里改成自己好记的访问码。

## 五、常见操作指引

### 5.1 导入名单（需管理员设备）

1. 在**管理端口**（8091）左侧「🏢 宿舍与人员」→ 右上「📥 导入人员信息」。
2. 选 Excel / CSV（不确定格式先点「下载导入模板」）。
3. 预览：识别到的列、每间寝室人数、新增/重复人员、寝室长标记情况；导入方式选**追加/更新**（日常补人）或**覆盖**（名单大改）。
4. 点「开始导入」。

### 5.2 配置寝室长验证（推荐）

1. 管理端口「管理控制台 → 寝室长验证密码」→ 在每行的输入框里**填自己想设的密码**点「保存」，或点「随机」；也可以「给没有密码的寝室批量生成」。
2. 复制弹窗里的「填报网址 / 宿舍号 / 验证密码」，发到对应宿舍群。
3. 寝室长打开**公开端口** →「我是寝室长（验证）」→ 输入宿舍号和密码 → 进入只属于自己的界面（寝室锁定、看不到别人寝室）。
4. 不设密码的寝室，寝室长和同学一样直接选寝室填写，不耽误事。

### 5.3 换电脑 / 换手机管理

1. 已授权的设备打开「管理控制台」，看「访问码」（形如 `484546`）。
2. 新设备打开网址 →「管理员进入」→ 输入访问码和给设备起的名字 → 保存。
3. 旧设备不用了就回控制台点「移除」。

### 5.4 改汇报时间 / 公告 / 缺席原因（需管理员设备）

「⚙️ 系统配置 · 基本设置」：填报截止时间（默认 22:00）、QQ 群汇报时间（默认 22:40）、自动导出时间（默认 23:30）、缺席原因候选项、首页公告、学校 / 班级 / 汇报人署名。保存后立即生效，定时任务自动重载。

### 5.5 对接 QQ 官方机器人

1. 到 [QQ 开放平台](https://q.qq.com/) 注册机器人，拿到 `AppID` 与 `AppSecret`，把机器人拉进汇报群。
2. 「系统配置 · QQ 机器人」填 AppID、AppSecret、汇报群 openid、是否 @全体成员、是否启用。
3. 点「检测连接」→ 能看到机器人信息就通了；点「发送测试消息」确认群里能收到。
4. 想让寝室长在群里直接填报，把机器人配置成 WebSocket 长连接模式，本系统通过 `/api/qqbot/events` 接收群消息并自动记录。

### 5.6 定时提醒

「提醒推送」页可添加多条定时提醒（每条自定义时间、内容，可选 @全体成员），内容支持 `{missing}`、`{missing_list}` 等变量；也可以点「推送提醒」立即把当前未填报宿舍发到群里。

### 5.7 导出 Excel

| 入口 | 用途 |
| --- | --- |
| 「📈 统计图表」右上 | 导出当前区间 Excel，或按天打包 zip |
| 「📚 填报记录」右上 | 导出查询区间；「服务器已存文件」下载每天自动存的 |
| 「⚙️ 系统配置 · 系统与备份」 | 导出最近 30 天、导出全部人员名单 |
| 服务器 `data/exports/` | 每天 23:30 自动生成 |

## 六、脚本与自检

### 6.1 接口自检（91 项）


## 七、数据存放与备份

| 内容 | 位置 |
| --- | --- |
| 数据库（寝室、人员、填报、配置、日志、设备授权） | `data/app.db`（含 `-wal` / `-shm`） |
| 每天自动导出的 Excel | `data/exports/宿舍填报_YYYY-MM-DD.xlsx` |
| 手动下载的备份 | `data/backups/app_YYYYmmdd_HHMMSS.db` |
| 服务日志（systemd 部署） | `data/logs/service.log` |

**备份建议**

1. 网页上「系统配置 · 系统与备份 → 下载数据库备份」（内部用 SQLite `.backup`，WAL 数据不会丢）。
2. 服务器定时备份：

   ```bash
   sqlite3 /www/dorm-data/app.db ".backup '/www/dorm-data/backups/app_$(date +%F).db'"
   find /www/dorm-data/backups -name 'app_*.db' -mtime +30 -delete
   ```

3. 导出的 Excel 每周拷一份到电脑或对象存储。
4. 迁移服务器：整个 `data/` 目录拷过去即可（设备授权名单也在库里，换机后需要重新授权设备）。

## 八、常见问题

**1. 管理页面打不开 / 提示需要授权**
正常现象：管理页面只对授权设备开放。在已授权设备上打开「管理控制台」看访问码，或到服务器执行 `.venv/bin/python scripts/show_admin_code.py`。

**2. 访问码忘了**
服务器上执行 `.venv/bin/python scripts/show_admin_code.py`（会显示当前码）；想换一个就加 `--reset`。

**3. 寝室长说密码不对 / 忘了密码**
「管理控制台 → 寝室长验证密码」里点该寝室的「**重置**」，会随机生成一个新密码，旧密码立即失效，把新的发给他即可。
想换成自己指定的密码：在输入框填好再点「改密码」。想彻底不限制这间寝室：点「**取消密码**」，它就恢复成"谁都能直接选它填报"。

**4. 想取消某间寝室的密码限制**
「管理控制台」→ 该寝室那一行的「**取消密码**」→ 确认。取消后这间寝室所有人都能直接填报（其他设了密码的寝室不受影响）。

**5. 同学说找不到自己的寝室**
入口页搜索框输入宿舍号（如 `6-213`）；确实没有就让管理员在「宿舍与人员」导入或新增。也可以在网址里带上寝室：`/?room=6-213#/report`。

**6. 手机打不开电脑上的服务**
确认同一 WiFi、用电脑局域网 IP、放行 8090 端口（命令见第四节）。

**7. 群汇报发了但群里没收到**
按顺序查：机器人 AppID / AppSecret / 群 openid → 「提醒推送」页「检测机器人连接」→ 「推送日志」里那次发送的失败原因（通常是群 openid 错、机器人不在群里、或机器人未启用）。

**8. 到点了定时任务没执行**
看「系统配置 · 定时任务」的“下次执行时间”，确认服务器时区（`timedatectl`）和服务在运行（`systemctl status dorm`）。服务停止期间的任务不会补发。

**9. 数据想放到大盘 / 别的目录**
设 `DORM_DATA_DIR`（服务器上改 systemd 里的 `Environment=DORM_DATA_DIR=/www/dorm-data`）。

**10. 没有外网能用吗**
能。前端资源全部本地，二维码本机生成；只有 QQ 官方机器人汇报需要能访问 QQ 开放平台接口。
