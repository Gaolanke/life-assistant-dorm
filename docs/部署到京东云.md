# 部署到京东云（Ubuntu 22.04）

本文是从零把「生活助手」部署到京东云服务器、并绑定自有域名的完整步骤。全程使用 `/www/dorm` 作为代码目录、`/www/dorm-data` 作为数据目录、`dorm` 作为服务名、`dorm.example.com` 作为示例域名。

> 阅读前请先确认：你已经拿到京东云服务器的公网 IP、root（或 sudo）权限，以及域名的 DNS 管理权限。

## 目标架构

```text
用户手机 / 电脑
      │  HTTPS 443
      ▼
   Nginx（反代 + 证书）          只暴露 80 / 443
      │  http://127.0.0.1:8090
      ▼
   Uvicorn + FastAPI（systemd 服务 dorm）
      │
      ├── /www/dorm-data/app.db        SQLite 数据库
      ├── /www/dorm-data/exports/      每天 23:30 自动导出的 Excel
      └── /www/dorm-data/logs/         服务日志

   QQ 官方机器人（QQ 开放平台）
      │  WebSocket 长连接
      └── https://dorm.example.com/api/qqbot/events
```

## 一、开通服务器与放行端口

### 1. 服务器规格

| 项目 | 建议 |
| --- | --- |
| 系统 | Ubuntu 22.04 LTS 64 位 |
| 配置 | 2 核 2 GB 起 |
| 系统盘 | 40 GB 起 |
| 数据盘 | 可选，挂载后把 `DORM_DATA_DIR` 指过去（例：挂到 `/www`） |
| 公网 IP | 必须有，且域名解析指向它 |

### 2. 京东云安全组规则

在「云主机 → 安全组」里确认入站规则：

| 方向 | 协议 | 端口 | 来源 | 说明 |
| --- | --- | --- | --- | --- |
| 入站 | TCP | 22 | 你的办公/家庭公网 IP | SSH 登录，**不要开 0.0.0.0/0** |
| 入站 | TCP | 80 | 0.0.0.0/0 | HTTP，用于签发证书和跳转 HTTPS |
| 入站 | TCP | 443 | 0.0.0.0/0 | HTTPS |
| 入站 | TCP | 8090 | 0.0.0.0/0 | 同学填报 + 寝室长界面（公开端口，必须放行） |
| 入站 | TCP | 8091 | 你的办公/家庭公网 IP | 管理员界面（管理端口，建议只给固定 IP；也可以完全不放行，用 ssh -L 8091:127.0.0.1:8091 root@服务器IP 隧道访问） |
| 入站 | 全部 | 其他 | — | **不开**。QQ 官方机器人走 WebSocket 长连接，无需开放额外端口 |

### 3. 登录服务器

```bash
ssh root@<你的服务器公网IP>
```

后续所有命令都在这台服务器上执行。

## 二、配置域名解析

在域名的 DNS 管理后台添加一条 A 记录：

| 记录类型 | 主机记录 | 记录值 | TTL |
| --- | --- | --- | --- |
| A | `dorm` | `<服务器公网IP>` | 600 |

解析生效后验证（在服务器或本地电脑执行）：

```bash
dig +short dorm.example.com
# 输出应为你的服务器公网 IP
```

> **备案提醒**：京东云中国大陆地域的服务器，域名必须完成 ICP 备案才能用 80/443 对外提供服务。如果还没备案，用 `http://<公网IP>:8090` 只能自己调试，不要指望公网用户能访问。

```bash
python3.11 -V
# Python 3.11.x
```

```bash
# Time zone: Asia/Shanghai (CST, +0800)
```

## 四、下载项目

### 方式 A：git clone（推荐）

```bash
# 建好目录（/www 也可以挂成数据盘）
mkdir -p /www
cd /www

# 换成你的仓库地址
git clone <你的仓库地址> dorm
cd /www/dorm
```

私有仓库首次 clone 会要求输入用户名和访问令牌（Token），不是账号密码。

### 方式 B：本地打包上传

在本地项目根目录（`E:\Document\code\生活助手`）执行：

```powershell
# 只打包代码，不带虚拟环境和运行数据
tar -czf dorm.tar.gz --exclude=.venv --exclude=__pycache__ --exclude=data --exclude=data_test .

# 上传到服务器
scp dorm.tar.gz root@<服务器公网IP>:/www/
```

在服务器上解包：

```bash
cd /www && mkdir -p dorm && tar -xzf dorm.tar.gz -C dorm && cd /www/dorm && ls
```

上传完成后确认关键文件存在：

```bash
cd /www/dorm
ls run.py requirements.txt backend/main.py deploy/dorm.service
```

## 五、创建虚拟环境并安装依赖

```bash
cd /www/dorm

# 创建虚拟环境
python3.11 -m venv .venv

# 升级 pip
.venv/bin/python -m pip install --upgrade pip

# 安装依赖
.venv/bin/pip install -r requirements.txt
```

### 镜像备选

如果官方源太慢或超时，换阿里云源：

```bash
.venv/bin/pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

只有内网可访问的机器，可以临时用清华源试一次：

```bash
.venv/bin/pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple/
```

> 本机打包测试时的结论是：**清华 PyPI 镜像不可达，用默认官方源可以正常安装**。在服务器上优先用官方源，慢再用阿里云。

### 二维码依赖（已包含在 requirements.txt 里）

二维码接口 `/api/system/qrcode` 依赖 `segno`，`requirements.txt` 里已经写好 `segno==1.6.6`，正常装依赖就会有。万一清单被改动导致缺失，单独补装一次：

```bash
.venv/bin/pip install segno==1.6.6
```

### 验证依赖装好了

```bash
cd /www/dorm
.venv/bin/python -c "import fastapi, sqlalchemy, apscheduler, httpx, openpyxl, segno, uvicorn; print('依赖 OK')"

# 能打印应用标题就说明代码可正常导入
DORM_DATA_DIR=/www/dorm-data .venv/bin/python -c "from backend.main import app; print(app.title)"
```

### 建好数据目录并交给运行用户

服务用 `www-data` 运行，数据目录必须提前建好并且**属主正确**（否则服务启动时写日志会失败）：

```bash
mkdir -p /www/dorm-data/{exports,backups,uploads,logs}
chown -R www-data:www-data /www/dorm-data
chmod 750 /www/dorm-data
ls -ld /www/dorm-data /www/dorm-data/logs
```

## 六、用 systemd 常驻运行

### 方式 A：一键部署脚本（推荐）

项目里已经带了一键脚本 `deploy/install.sh`，它会把代码同步到 `/www/dorm`、建 venv、装依赖、建好数据目录并交给 `www-data`、写入 systemd 服务（**默认同时监听 8090 和 8091，不启用 Nginx、不碰 80 端口**）、生成管理访问码，最后跑一次接口自检：

```bash
cd /www/dorm
sudo bash deploy/install.sh

# 想自定义目录或域名：
sudo APP_DIR=/www/dorm DATA_DIR=/www/dorm-data DOMAIN=dorm.example.com bash deploy/install.sh
```

脚本执行完用下面两条命令确认服务在跑：

```bash
systemctl status dorm --no-pager
curl -s http://127.0.0.1:8090/api/health
# {"ok":true,"app":"生活助手",...}
```

脚本会提示是否自检通过；自检日志同时在 `/tmp/dorm_selftest.log`。如果脚本因为环境差异中断，按下面的「方式 B」逐步手动执行即可，两种方式结果一致。

<details>
<summary>方式 A 的注意事项（脚本做了什么、不会做什么）</summary>

- 会安装 `python3 python3-venv python3-pip curl ca-certificates`（`WITH_NGINX=1` 时才装 Nginx）；
- 默认 `PORT=8090 ADMIN_PORT=8091 BIND=0.0.0.0`：同学用 `http://服务器IP:8090`，管理员用 `http://服务器IP:8091`；
- 要域名就加 `WITH_NGINX=1 DOMAIN=你的域名`（Nginx 只反代 8090，管理端口仍走 IP 或 SSH 隧道）；
- 代码同步时**不覆盖**目标机的 `data/` 目录；
- `DORM_DEV_AUTOLOGIN` 不会被写入（该变量只用于本地截图调试，正式环境不需要）；
- 不会替你申请 HTTPS 证书，证书在第七节用 certbot 完成。

</details>

### 方式 B：手动配置 systemd

**1. 把服务模板复制到系统目录**

```bash
cp /www/dorm/deploy/dorm.service /etc/systemd/system/dorm.service
```

**2. 完整的 `/etc/systemd/system/dorm.service` 内容**

项目自带的模板如下，直接用 `tee` 写入也可以：

```bash
tee /etc/systemd/system/dorm.service > /dev/null <<'EOF'
[Unit]
Description=Dorm Management System (FastAPI)
Documentation=file:///www/dorm/README.md
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/www/dorm
# 数据（SQLite、导出的 Excel、备份、日志）单独放到 /www/dorm-data，方便备份和扩容
Environment=DORM_HOST=0.0.0.0
Environment=DORM_PORT=8090
Environment=DORM_ADMIN_PORT=8091
Environment=DORM_DATA_DIR=/www/dorm-data
Environment=DORM_TIMEZONE=Asia/Shanghai
Environment=PYTHONUNBUFFERED=1
# 注意：正式环境千万不要设置 DORM_DEV_AUTOLOGIN
ExecStart=/www/dorm/.venv/bin/python run.py
Restart=always
RestartSec=5
StandardOutput=append:/www/dorm-data/logs/service.log
StandardError=append:/www/dorm-data/logs/service.log

[Install]
WantedBy=multi-user.target
EOF
```

**3. 启动并设置开机自启**

```bash
systemctl daemon-reload          # 重新读取服务文件
systemctl enable dorm            # 开机自启
systemctl start dorm             # 启动
systemctl status dorm --no-pager # 看状态，应为 active (running)
```

**4. 常用管理命令**

```bash
systemctl restart dorm   # 重启（改代码、改 .service 后执行）
systemctl stop dorm      # 停止
systemctl start dorm     # 启动
systemctl disable dorm   # 取消开机自启
systemctl is-active dorm # 只输出 active / inactive
systemctl is-enabled dorm
```

**6. 确认服务真的正常**

```bash
curl -s http://127.0.0.1:8090/api/health
curl -s http://127.0.0.1:8090/api/system/info
systemctl status dorm --no-pager | head -20
```

`/api/health` 返回 `{"ok":true,...}`、`status` 是 `active (running)` 就通过了。

### 常见启动失败与对应处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `status=200/CHDIR` | `WorkingDirectory=/www/dorm` 不存在 | 确认项目路径，或改服务里的路径 |
| `status=200/STDERR` 或日志文件打不开 | `/www/dorm-data/logs` 不存在或属主不对 | `mkdir -p /www/dorm-data/logs && chown -R www-data:www-data /www/dorm-data` |
| `ModuleNotFoundError: No module named 'backend'` | `WorkingDirectory` 不对，或 venv 路径写错 | 确认 `WorkingDirectory=/www/dorm`、`ExecStart` 用 `/www/dorm/.venv/bin/python` |
| `ModuleNotFoundError: No module named 'segno'` | 漏装二维码依赖 | `.venv/bin/pip install segno==1.6.6 && systemctl restart dorm` |
| `Address already in use` | 8090 或 8091 被占 | `ss -lntp | grep -E ":(8090|8091)"` 找到进程后停掉，或改 `DORM_PORT` / `DORM_ADMIN_PORT` 再重跑 install.sh |

## 七、配置 Nginx 反向代理（可选；不用域名可以跳过）

> 默认部署**不启用 Nginx、不占用 80 端口**：同学用 `http://服务器IP:8090`，管理员用 `http://服务器IP:8091`（管理接口只在 8091 生效）。
> 只有要用域名 + HTTPS 时才需要本节，并且要改用 `WITH_NGINX=1` 重新执行安装脚本，或在下面手动配置。

Nginx 对外提供 80/443，内部转发到 `127.0.0.1:8090`。

### 1. 写站点配置

```bash
tee /etc/nginx/sites-available/dorm > /dev/null <<'EOF'
# HTTP：先跑通，证书签发后 certbot 会自动改写这里加上跳转
server {
    listen 80;
    listen [::]:80;
    server_name dorm.example.com;

    client_max_body_size 20m;      # 导入名单的 Excel 可能比较大
    access_log /var/log/nginx/dorm.access.log;
    error_log  /var/log/nginx/dorm.error.log;

    location / {
        proxy_pass http://127.0.0.1:8090;
        proxy_http_version 1.1;

        # 让后端能取到真实客户端 IP（审计日志记的就是它）
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 长连接与超时
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_connect_timeout 30s;
        proxy_send_timeout    120s;
        proxy_read_timeout    120s;
    }
}
EOF
```

把 `dorm.example.com` 全部替换成你的真实域名：

```bash
sed -i 's/dorm.example.com/你的域名/g' /etc/nginx/sites-available/dorm
```

### 2. 启用站点并检查语法

```bash
ln -sf /etc/nginx/sites-available/dorm /etc/nginx/sites-enabled/dorm

# 检查配置语法，必须输出 syntax is ok / test is successful
nginx -t

systemctl reload nginx
```

### 3. 验证反代

```bash
curl -I http://dorm.example.com/
# HTTP/1.1 200 OK

curl -s http://dorm.example.com/api/health
# {"ok":true,...}
```

浏览器打开 `http://服务器IP:8090`（或已配好的域名）能看到「选择寝室」入口页就说明这一阶段完成了。

> **可选**：把服务器 IP 直接访问的请求也转给这个站点（不放域名解析也能临时看）。在同一个文件里再加一个 `server { listen 80 default_server; server_name _; ... }` 段落，`location` 内容与上面一致即可。宿主机上有其他站点时不要重复使用 `default_server`。

## 八、用 certbot 配置 HTTPS

### 1. 安装 certbot

```bash
apt install -y certbot python3-certbot-nginx
```

### 2. 签发并自动配置

```bash
certbot --nginx -d dorm.example.com
```

交互过程：

1. 输入邮箱（接收证书到期提醒）。
2. 同意服务条款：输入 `Y`。
3. 选择是否把 HTTP 请求跳转到 HTTPS：**选 2（Redirect）**。

证书路径（certbot 自动写入 Nginx 配置）：

```text
/etc/letsencrypt/live/dorm.example.com/fullchain.pem
/etc/letsencrypt/live/dorm.example.com/privkey.pem
```

### 3. 验证

```bash
certbot certificates
# 应显示证书与到期时间

curl -I https://dorm.example.com/
# HTTP/2 200

# 确认 HTTP 会跳转到 HTTPS
curl -I http://dorm.example.com/
# HTTP/1.1 301 ... Location: https://dorm.example.com/
```

### 4. 自动续期

certbot 安装时会自动创建 systemd 定时器，确认一下即可：

```bash
systemctl status certbot.timer --no-pager
systemctl list-timers | grep certbot

# 手动演练续期（不会真的换证书）
certbot renew --dry-run
```

### 5. 改完 Nginx 后的固定动作

```bash
nginx -t && systemctl reload nginx
```

## 九、首次启动后必须做的事

按顺序做完下面 7 步，系统才算正式可用。

### 1. 授权管理设备（管理页面只对授权设备开放）

浏览器打开服务地址（默认 `http://服务器IP:8090/`），会直接进入「请选择你的寝室」入口页。

- **普通同学**：选自己的寝室 → 直接填写，不需要账号。
- **寝室长**：入口页「我是寝室长（验证）」→ 输入宿舍号和密码（密码在管理控制台生成）。
- **管理员**：入口页「管理员进入」→ 输入管理访问码。

**先说清楚两个端口**：

| 端口 | 用途 | 谁能访问 |
| --- | --- | --- |
| `8090` | 同学选寝室填报 + 寝室长界面 | 公开，安全组要放行 |
| `8091` | 管理员界面与全部管理接口（改配置、导名单、设备授权、清空数据……只在 8091 生效） | 建议只对固定 IP 放行，或干脆不放行、用 SSH 隧道 |

第一次拿访问码，在服务器上执行：

```bash
cd /www/dorm
.venv/bin/python scripts/show_admin_code.py            # 显示当前访问码
.venv/bin/python scripts/show_admin_code.py --reset    # 换一个访问码
.venv/bin/python scripts/show_admin_code.py --devices  # 看看已授权的设备
```

拿到访问码后，在需要管理的电脑 / 手机上打开 **管理端口** `http://服务器IP:8091` → 输入访问码 → 给设备起个名字。之后在「管理控制台 → 设备授权」里可以查看访问码、停用或移除设备；换电脑时用同一个访问码授权新设备即可。

> 访问码可以在「管理控制台」里点「修改」自己定一个（4 位以上），也可以「随机生成」换掉。
> 想彻底关闭设备门禁（任何人可进管理页面）：在「系统配置 · 基本设置」把 `admin_access` 设为 0。

### 2. 清空演示数据

「⚙️ 系统配置 · 系统与备份 · 危险操作」→「清空全部业务数据」→ 按提示输入“清空”确认。

会删除所有宿舍、人员、填报记录、推送日志；**系统配置（汇报时间、模板、机器人地址等）保留**。此操作不可恢复，先做一次备份更稳。

### 3. 改基本配置

「⚙️ 系统配置 · 基本设置」把下面的值改成真实信息：

| 配置项 | 填什么 |
| --- | --- |
| 学校名称 | 你的学校全称 |
| 班级名称 | 例如 `物联网 25-2 班` |
| 汇报人署名 | 例如“生活委员 张三” |
| 接收汇报的老师 | 班主任姓名 |
| 每晚填报截止时间 | 例如 `22:00` |
| 每晚 QQ 群汇报时间 | 例如 `22:40` |

保存后到「定时任务」页签确认三个任务的**下次执行时间**已按新时间生效。

### 4. 导入真实名单

### 7. 接入 QQ 官方机器人

## 十二、防火墙与安全组：只暴露 80/443

对外只有 80 和 443，其余端口一律不开放。

### 1. 京东云安全组（最终状态）

| 方向 | 协议 | 端口 | 来源 | 用途 |
| --- | --- | --- | --- | --- |
| 入站 | TCP | 22 | 你的固定公网 IP | 运维 SSH |
| 入站 | TCP | 80 | 0.0.0.0/0 | HTTP（跳转 HTTPS + 证书续期） |
| 入站 | TCP | 443 | 0.0.0.0/0 | HTTPS |
| 入站 | 其他 | 其他 | — | **全部拒绝**（默认策略） |
| 出站 | 全部 | 全部 | 0.0.0.0/0 | 允许（需要访问 QQ 开放平台） |

**8091 不加规则**：管理端口 8091 只在需要时对固定 IP 放行（或走 SSH 隧道）；8090 要对外放行给同学填报。

### 2. 服务器本机 UFW

```bash
apt install -y ufw
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable
ufw status verbose
```

预期输出：

```text
Status: active
To                         Action      From
--                         ------      ----
22/tcp                     ALLOW       Anywhere
80/tcp                     ALLOW       Anywhere
443/tcp                    ALLOW       Anywhere
```

> 先确认 SSH 端口再开 UFW，避免把自己关在门外。用非 22 端口的把上面的 `22` 换成实际端口。

### 3. 确认服务只监听本机

```bash
ss -lntp | grep -E ':(8090|8091)'
# 期望看到 127.0.0.1:8090 和 127.0.0.1:8091

ss -lntp | grep -E ':(80|443)'
# 期望看到 0.0.0.0:80 和 0.0.0.0:443（由 Nginx 监听）
```

`dorm.service` 里已经写了 `DORM_HOST=127.0.0.1`，Uvicorn 不会对公网暴露 8090。

## 十三、日志排查命令

### 1. systemd 服务日志（后端）

```bash
# 实时跟踪
journalctl -u dorm -f

journalctl -u dorm -n 200 --no-pager

journalctl -u dorm --since today

journalctl -u dorm -p err --no-pager

# 某个时间段
journalctl -u dorm --since "2026-10-10 20:00" --until "2026-10-10 23:59"
```

### 2. 数据目录下的日志文件

`dorm.service` 把标准输出和错误都追加到 `/www/dorm-data/logs/service.log`：

```bash
# 实时跟踪
tail -f /www/dorm-data/logs/service.log

# 最近 300 行
tail -n 300 /www/dorm-data/logs/service.log

# 只看定时任务相关记录
grep -E "定时任务|群汇报|自动导出|未填报提醒" /www/dorm-data/logs/service.log | tail -n 50

# 只看失败堆栈
grep -n "失败\|ERROR\|Traceback" /www/dorm-data/logs/service.log | tail -n 50
```

定时任务的关键日志字样：`定时任务已启动`、`QQ 群汇报完成`、`未填报提醒完成`、`已自动导出：宿舍填报_YYYY-MM-DD.xlsx`；失败时会有 `QQ 群汇报失败`、`自动导出失败` 加堆栈。

日志按大小切割（可选）：

```bash
tee /etc/logrotate.d/dorm > /dev/null <<'EOF'
/www/dorm-data/logs/service.log {
    daily
    rotate 14
    missingok
    notifempty
    copytruncate
}
EOF
```

### 3. Nginx 日志

```bash
tail -f /var/log/nginx/dorm.access.log     # 访问记录，排查 4xx/5xx
```

`502 Bad Gateway` 说明 Nginx 连不上后端：先 `systemctl status dorm --no-pager`，再 `curl -s http://127.0.0.1:8090/api/health` 定位。

| 想看什么 | 在哪看 |

## 十四、备份与升级

### 1. 备份

**方式 A：网页下载（随时可用）**

管理员登录 →「⚙️ 系统配置 · 系统与备份」→「下载数据库备份」。`GET /api/system/backup` 用 SQLite 官方 backup API 生成，已把 WAL 里的最新数据合并进去，下载到的 `.db` 文件是完整快照，同时留在 `/www/dorm-data/backups/`。

**方式 B：服务端定时备份（推荐长期保留）**

```bash
mkdir -p /www/backup

# 每天 03:20 备份一次，保留最近 30 天
crontab -e
```

写入：

```cron
20 3 * * * sqlite3 /www/dorm-data/app.db ".backup '/www/backup/app_$(date +\%F).db'" && find /www/backup -name 'app_*.db' -mtime +30 -delete
```

> 用 `.backup`（SQLite 官方接口）而不是直接 `cp`，否则可能漏掉 WAL 里未落盘的数据。没有 `sqlite3` 命令就先 `apt install -y sqlite3`。

**方式 C：连同导出文件一起归档**

```bash
# 把数据库和每天的 Excel 打包留存
tar -czf /www/backup/dorm_full_$(date +%F).tar.gz /www/dorm-data/app.db /www/dorm-data/exports
```

### 2. 恢复

```bash
# 1. 停服务
systemctl stop dorm

# 2. 备份当前(损坏的)数据库，避免不可逆
mv /www/dorm-data/app.db /www/dorm-data/app.db.broken

# 3. 放入备份文件
cp /www/backup/app_2026-10-09.db /www/dorm-data/app.db

# 4. 删掉旧的 WAL/SHM，让 SQLite 重新生成
rm -f /www/dorm-data/app.db-wal /www/dorm-data/app.db-shm

# 5. 修正属主并启动
chown www-data:www-data /www/dorm-data/app.db
systemctl start dorm
systemctl status dorm --no-pager
curl -s http://127.0.0.1:8090/api/health
```

### 3. 升级

**第 1 步：先备份（必须）**

```bash
cd /www/dorm
.venv/bin/python -c "import fastapi, sqlalchemy, apscheduler, httpx, openpyxl, segno, uvicorn; print('依赖 OK')"  # 确认依赖完整
sqlite3 /www/dorm-data/app.db ".backup '/www/backup/before_upgrade_$(date +%F_%H%M).db'"
ls -lh /www/backup/
```

**第 2 步：拉代码**

```bash
cd /www/dorm
git pull
```

如果是打包上传的方式，就把新包解压覆盖代码目录（**不要覆盖 `/www/dorm-data`**，它不在代码目录里）。

**第 3 步：更新依赖**

```bash
cd /www/dorm
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install segno==1.6.6    # 二维码依赖，防止清单漏行
```

**第 4 步：重启服务**

```bash
systemctl restart dorm
systemctl status dorm --no-pager | head -15
journalctl -u dorm -n 50 --no-pager      # 确认没有异常堆栈
```

**第 5 步：升级后验证**

```bash
cd /www/dorm
.venv/bin/python scripts/selftest.py https://dorm.example.com
```

输出 `通过 87 项，失败 0 项` 即可。最后在浏览器里刷新页面，检查「数据看板」和「定时任务」页签正常。

**第 6 步：回滚（出问题时）**

```bash
cd /www/dorm
git log --oneline -5                 # 找到上一个可用提交
git checkout <上一个提交的哈希>
.venv/bin/pip install -r requirements.txt
systemctl restart dorm
```

数据库结构有变化时，还需要按上面的「恢复」步骤把升级前的 `.db` 放回去。

## 十五、Windows Server 部署备选方案

如果只能用 Windows Server（2016 / 2019 / 2022），按下面做。系统本身在 Windows 上完全可用（本地开发环境就是 Windows + Python 3.11.9）。

### 1. 准备环境

1. 安装 **Python 3.11**（官网安装包，勾选 `Add python.exe to PATH`）。
2. 安装 **Nginx for Windows**，解压到 `C:\nginx`。
3. 把项目放到 `C:\dorm`。

### 2. 建虚拟环境、装依赖、试跑

```powershell
cd C:\dorm
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install segno==1.6.6

# 前台试跑，确认能起来
$env:DORM_DATA_DIR = "D:\dorm-data"
$env:DORM_HOST = "127.0.0.1"
$env:DORM_PORT = "8090"
$env:DORM_TIMEZONE = "Asia/Shanghai"
.\.venv\Scripts\python.exe run.py
```

浏览器访问 `http://127.0.0.1:8090` 能打开即通过，按 `Ctrl + C` 停止。

### 3. 用 NSSM 注册成 Windows 服务

```powershell
# 下载 nssm.exe 放到 C:\nssm\nssm.exe
C:\nssm\nssm.exe install DormSystem "C:\dorm\.venv\Scripts\python.exe" "C:\dorm\run.py"

# 设置工作目录与环境变量
C:\nssm\nssm.exe set DormSystem AppDirectory "C:\dorm"
C:\nssm\nssm.exe set DormSystem AppEnvironmentExtra "DORM_HOST=127.0.0.1" "DORM_PORT=8090" "DORM_DATA_DIR=D:\dorm-data" "DORM_TIMEZONE=Asia/Shanghai" "PYTHONUNBUFFERED=1"

# 日志与自动重启
C:\nssm\nssm.exe set DormSystem AppStdout "D:\dorm-data\logs\service.log"
C:\nssm\nssm.exe set DormSystem AppStderr "D:\dorm-data\logs\service.log"
C:\nssm\nssm.exe set DormSystem AppExit Default Restart
C:\nssm\nssm.exe set DormSystem Start SERVICE_AUTO_START

# 启服务
C:\nssm\nssm.exe start DormSystem
Get-Service DormSystem
```

手动建好日志目录：`New-Item -ItemType Directory -Force D:\dorm-data\logs`。

也可以用项目自带的 `deploy\start.bat` 做前台启动脚本（它会自动建 venv、装依赖、启动服务），再交给「任务计划程序」在开机时运行：

```powershell
# 任务计划程序 → 创建任务 → 触发器“计算机启动时” → 操作“启动程序”
# 程序：C:\dorm\deploy\start.bat
# 起始于：C:\dorm
# 勾选“不管用户是否登录都要运行”
```

`deploy\start.bat` 默认用 8090 端口，也可以带参数指定，例如 `start.bat 8080`。

### 4. Nginx for Windows 反向代理

`C:\nginx\conf\nginx.conf` 的 `http { }` 里加：

```nginx
server {
    listen       80;
    server_name  dorm.example.com;

    client_max_body_size 20m;

    location / {
        proxy_pass http://127.0.0.1:8090;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        "upgrade";
        proxy_read_timeout 120s;
    }
}
```

启动与重载：

```powershell
cd C:\nginx
start nginx            # 启动
.\nginx.exe -s reload  # 改配置后重载
.\nginx.exe -t         # 只检查语法
.\nginx.exe -s stop    # 停止
```

给 Nginx 也注册成服务，同样用 NSSM：

```powershell
C:\nssm\nssm.exe install DormNginx "C:\nginx\nginx.exe"
C:\nssm\nssm.exe set DormNginx AppDirectory "C:\nginx"
C:\nssm\nssm.exe set DormNginx Start SERVICE_AUTO_START
C:\nssm\nssm.exe start DormNginx
```

### 5. HTTPS

Windows 上优先在**前置的云负载均衡 / CDN** 上终结 HTTPS，回源到 `http://服务器IP:80`，这样证书续期由云平台负责。如果必须在 Windows 上直接签证书，用 **win-acme**（wacs.exe）按向导为 `dorm.example.com` 申请 Let's Encrypt 证书，并选择「把证书绑定到 IIS 或保存为 PEM 供 Nginx 使用」，然后在 Nginx 的 `server` 块里加：

```nginx
listen 443 ssl;
ssl_certificate     C:/nginx/certs/dorm.example.com-chain.pem;
ssl_certificate_key C:/nginx/certs/dorm.example.com-key.pem;
```

### 6. Windows 上的差异提醒

| 项目 | 说明 |
| --- | --- |
| 防火墙 | 放行入站 TCP 80/443：`New-NetFirewallRule -DisplayName "dorm-web" -Direction Inbound -Protocol TCP -LocalPort 80,443 -Action Allow` |
| systemd | 不可用，用 NSSM 或任务计划程序代替 |
| 安全组 | 云主机控制台的安全组规则与 Linux 相同：只开 22（或 3389）、80、443 |
| QQ 官方机器人 | 到 QQ 开放平台注册机器人、填 AppID / AppSecret / 群 openid，走 WebSocket 长连接，无需本机协议端 |
| 脚本路径 | 文档里的 `.venv/bin/python` 换成 `.venv\Scripts\python.exe` |
| 远程桌面 | 3389 只在必要时开，并且来源限制为固定 IP |

## 附录：deploy 目录里有什么

`deploy/` 下有三个文件，都在项目里，不需要另外创建：

| 文件 | 用途 |
| --- | --- |
| `deploy/install.sh` | Ubuntu 一键部署：装系统依赖、同步代码、建 venv 装依赖、建数据目录并改属主、写 systemd 服务、配置并重载 Nginx、跑一次接口自检 |
| `deploy/dorm.service` | systemd 服务模板（内容与第六节「方式 B」一致），路径默认 `/www/dorm` 与 `/www/dorm-data` |
| `deploy/start.bat` | Windows 前台启动脚本：首次运行自动建 venv、装依赖，然后启动服务；可带端口参数，例如 `start.bat 8080` |

`install.sh` 已经包含 Nginx 反代配置和自检，执行一次就能得到一个可直接用域名访问的服务（HTTPS 在第七节用 certbot 补上）。

> 提示：`install.sh` 会先判断自带模板里的 `WorkingDirectory` 是否就是当前代码目录：一致就直接复用，不一致就按当前实际路径生成一份服务文件，避免路径写死导致启动失败。
